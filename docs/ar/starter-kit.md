# MajidaStarter: مرجع حزمة البداية

تُبنى فكّرون على حزمة MajidaStarter. يحتفظ هذا الملف بالمرجع على مستوى الحزمة (الميزات والإعدادات والحسابات التجريبية والخدمات والترجمة والأدوار وتوليد الموارد)، وهو المرجع الذي يحيل إليه [`README.md`](README.md) بهذه اللغة. ميزات فكّرون الخاصة موصوفة في ذلك الملف وفي [`docs/fakkroun/`](../fakkroun).

> لغات أخرى: [English](../en/starter-kit.md) · [Français](../fr/starter-kit.md)

## أبرز المزايا

- **مسار مصادقة كامل**: التسجيل وتسجيل الدخول والخروج وإعادة تعيين كلمة المرور والتحقق الاختياري من البريد الإلكتروني، وكلها مبنية كمكوّنات Livewire ذات ملف واحد. يسجّل اللاعبون ويدخلون بعنوان بريد إلكتروني **أو** رقم هاتف، ويستطيعون اللعب فوراً (دون خطوة تحقق). يُقيَّد تسجيل الدخول بالمعدل حسب البريد/الهاتف وعنوان IP.
- **التحقق الثنائي**: تطبيقات TOTP (RFC 6238) مع رموز استرداد تُستخدم مرة واحدة، وتُدار من **الإعدادات ← التحقق الثنائي**، وتُفرض عند تسجيل الدخول عبر الويب وواجهة API بعد تأكيده. لا تحتاج إلى أي اعتمادية إضافية.
- **لوحة الإدارة**: واجهة خلفية مخصصة ومحمية بالصلاحيات لإدارة المستخدمين والمقالات والفئات، ولمراجعة النشاط وتعديل إعدادات الموقع.
- **وحدة المحتوى**: عمليات إنشاء وقراءة وتعديل وحذف كاملة **للمقالات** و**الفئات** في لوحة الإدارة. تظهر المقالات المنشورة في `/blog` العام مع البحث وصفحات التفاصيل وصور الغلاف، و`/docs` هو الدليل داخل التطبيق. تذهب عمليات الحذف إلى **سلة المحذوفات** ويمكن استعادتها؛ والنشر والحذف الجماعي والتصفية والترتيب مدمجة في قوائم الإدارة.
- **التحكم في الوصول بالأدوار والصلاحيات**: مبني على [spatie/laravel-permission](https://spatie.be/docs/laravel-permission)، مع دور `admin` جاهز.
- **سجل النشاط**: كل تغيير مهم في المستخدمين والمقالات والفئات والإعدادات مسجّل بواسطة [spatie/laravel-activitylog](https://spatie.be/docs/laravel-activitylog) ويمكن تصفحه من لوحة الإدارة.
- **تصدير سجل النشاط والاحتفاظ به**: تنزيل السجل المصفّى بصيغة CSV أو JSON؛ ويعمل `activitylog:clean` يومياً عبر المجدول.
- **إشعارات CRUD**: يتلقى المديرون إشعاراً مخزّناً عند إنشاء المقالات أو الفئات أو المستخدمين أو الإعدادات أو تعديلها أو حذفها أو استعادتها، ويمكنهم مراجعتها في صفحة الإشعارات المرتبطة بالجرس. لا يُشعَر الشخص الذي أجرى التغيير بتغييره هو. انظر ملاحظات الميزات.
- **خريطة الموقع (XML)**: يكتب `php artisan sitemap:generate` الملف `/sitemap.xml` (عبر [spatie/laravel-sitemap](https://github.com/spatie/laravel-sitemap)) من الصفحات العامة والمقالات المنشورة؛ ويُعاد بناؤه كل ساعة من المجدول وبعد تغييرات المقالات، ويُعلَن عنه في `/robots.txt` ديناميكي. انظر ملاحظات الميزات.
- **الوسوم**: وسوم مقالات قابلة للترجمة عبر spatie/laravel-tags: منتقٍ قابل لإعادة الاستخدام في نموذج المقال، وشاشة وسوم في الإدارة، وتصفية في قائمة الإدارة، وعلى `/blog?tag=` وفي واجهة API.
- **البيانات المنظمة لتحسين محركات البحث وRSS**: JSON-LD من نوع schema.org (Organization وWebSite وBreadcrumbList وBlogPosting) عبر [spatie/schema-org](https://github.com/spatie/schema-org)، ووسوم canonical وOpen Graph، وخلاصة RSS على `/feed` عبر [spatie/laravel-feed](https://github.com/spatie/laravel-feed). تُولَّد المعرّفات النصية وتبقى ثابتة بفضل [spatie/laravel-sluggable](https://github.com/spatie/laravel-sluggable).
- **الحماية من الرسائل المزعجة**: نموذجا التسجيل ونسيان كلمة المرور يحتويان على حقل مصيدة وفحص للمدة ([spatie/laravel-honeypot](https://github.com/spatie/laravel-honeypot)).
- **النسخ الاحتياطية ومراقبة الصحة**: نسخ احتياطية مجدولة ومراقَبة لقاعدة البيانات والملفات المرفوعة ([spatie/laravel-backup](https://spatie.be/docs/laravel-backup))، وفحوص صحة للتطبيق ([spatie/laravel-health](https://spatie.be/docs/laravel-health))، ولكلٍّ منهما صفحة في الإدارة؛ و`/health.json` محمي برمز لأدوات المراقبة.
- **PDF وجداول البيانات**: ملفات PDF للمقالات من تخطيط Blade مشترك ([spatie/laravel-pdf](https://spatie.be/docs/laravel-pdf)، بمحرك DomPDF)، وتصدير CSV/XLSX بالتدفق واستيراد مُتحقَّق منه للفئات ([spatie/simple-excel](https://github.com/spatie/simple-excel)). انظر **[docs/spatie-integrations.md](../spatie-integrations.md)** لتفاصيل هذه الميزات.
- **إحصاءات الزيارات**: تُحسب مشاهدات الصفحات في الموقع العام (يُستثنى الروبوتات والإدارة وواجهة API وطلبات الملفات الثابتة) وتظهر في لوحات المعلومات.
- **صحة النظام**: تفحص لوحة الإدارة قاعدة البيانات والذاكرة المؤقتة والطابور، و`/up` نقطة فحص حياة لأدوات المراقبة.
- **واجهة REST**: كل خدمة مكشوفة كنقاط JSON تحت `/api`، ومحمية بالبوابات نفسها التي تحمي واجهة الويب. تُقبل جلسات الويب ورموز Sanctum الشخصية معاً (انظر [API](README.md)).
- **التعريب (i18n) ودعم RTL**: الإنجليزية والعربية والفرنسية متوفرة افتراضياً، مع مُبدّل للغة، وحفظ اللغة لكل جلسة، ومعالجة تلقائية لاتجاه النص.
- **إعدادات قابلة للترجمة**: يُخزَّن اسم الموقع ووصفه لكل لغة عبر [spatie/laravel-translatable](https://spatie.be/docs/laravel-translatable).
- **مفتاح السمة الفاتحة والداكنة**: مبدّل دائم بلا وميض.
- **وضع الصيانة**: يُفعَّل من إعدادات الإدارة؛ يحصل الزوار على صفحة 503 (أو JSON على `/api`)، بينما تبقى الإدارة وتسجيل الدخول وتبديل اللغة و`/up` متاحة.
- **الحذف الناعم وسلة المحذوفات**: تُحذف المستخدمين والمقالات والفئات حذفاً ناعماً، ويمكن استعادتها، ويمكن حذفها نهائياً.
- **السياسات**: الوصول إلى المقالات والفئات تفرضه `PostPolicy` و`CategoryPolicy` (لا يستطيع محررو المقالات تعديل غير مقالاتهم إلا إذا كانوا مديرين).
- **البريد في الطابور**: رسائل التحقق وإعادة تعيين كلمة المرور تُرسل عبر الطابور.
- **هيكل CRUD**: ينشئ `php artisan starter:make-crud Article` النموذج والترحيل والمصنع والخدمة والسياسة واختباراً لمورد جديد.
- **بنية موجهة بالخدمات**: منطق العمل في فئات خدمة مخصصة (`UserService` و`PostService` و`CategoryService` و`SettingService` وغيرها)، لا في المتحكمات أو المكوّنات.
- **واجهة أمامية حديثة**: Tailwind CSS 4 وVite 8، مهيأة وجاهزة للاستخدام.
- **مختبر ومحلَّل**: مجموعة اختبارات PHPUnit تغطي المصادقة والتحقق الثنائي والملفات الشخصية وصفحات الإدارة وإدارة المستخدمين والمقالات والفئات وواجهة API والإشعارات ووضع الصيانة والتعريب، إضافة إلى Pint (تنسيق الكود) وLarastan (التحليل الثابت)، وكلها تعمل في CI.

### ملاحظات الإنتاج

- **صور الغلاف وصور الملف الشخصي** تُخزَّن على القرص `public`. شغّل `php artisan storage:link` مرة واحدة لكل بيئة.
- **الطوابير**: تُوضع رسائل البريد في الطابور (`QUEUE_CONNECTION=database` افتراضياً). شغّل `php artisan queue:work` كعملية دائمة؛ و`composer dev` يشغّلها محلياً. بدون عامل، لا تُرسل رسائل التحقق وإعادة التعيين.
- **المجدول**: شغّل `php artisan schedule:work` محلياً، أو أضف `* * * * * php /path/to/artisan schedule:run` إلى cron في الإنتاج. يحذف المجدول سجل النشاط القديم، ويعيد بناء خريطة الموقع، ويشغّل فحوص الصحة كل دقيقة والنسخة الاحتياطية اليومية.
- **خريطة الموقع**: اضبط `APP_URL` على النطاق القياسي للإنتاج (مثلاً `https://www.example.com`)؛ فكل عناوين خريطة الموقع وrobots.txt مبنية منه، ويرفض التوليد المضيفين من نوع `localhost` أو `.test` في الإنتاج. يجب أن يتمكن مستخدم PHP الذي يشغّل المجدول والعامل من الكتابة في `public/`. شغّل `php artisan sitemap:generate` مرة واحدة بعد النشر.
- **صلاحيات جديدة**: بعد الترقية، شغّل `php artisan migrate --force` و`php artisan db:seed --class=RolesAndPermissionsSeeder --force` حتى يحصل دور المدير على `manage tags` و`view system health` و`manage backups`.
- **النسخ الاحتياطية**: يحتاج الخادم إلى `mysqldump` أو `pg_dump` أو `sqlite3` حسب محرك قاعدة البيانات. اضبط `BACKUP_NOTIFICATION_EMAIL` و، للأقراص خارج الموقع، `BACKUP_DISKS` و`BACKUP_ARCHIVE_PASSWORD`. تستثني الأرشيفات ملف `.env` والكود المصدري. خطوات الاستعادة: [docs/spatie-integrations.md#restoring](../spatie-integrations.md#restoring).
- **مراقبة الصحة**: يشغّل المجدول الفحوص كل دقيقة. اضبط `HEALTH_NOTIFICATION_EMAIL` للتنبيهات و`HEALTH_SECRET_TOKEN` لتفعيل `/health.json` لأدوات المراقبة الخارجية.
- **وضع الصيانة** يُدار من **الإدارة ← الإعدادات**؛ ولا يحتاج إلى `php artisan down`.
- **فحوص الصحة**: وجّه أدوات المراقبة إلى `/up`. تعرض بطاقة الصحة في لوحة الإدارة الفحوص نفسها بتفاصيل أكبر.
- **كلمات المرور**: تستخدم كل قواعد كلمة المرور `Password::defaults()`. وفي الإنتاج تشترط أيضاً حروفاً كبيرة وصغيرة وأرقاماً، وألا تكون كلمة المرور في قوائم التسريبات المعروفة. خارج الإنتاج، الحد الأدنى 8 خانات.
- **حدود المعدل**: نقاط `auth/login` و`auth/register` و`auth/token` في API تسمح بـ6 طلبات في الدقيقة لكل بريد إلكتروني وعنوان IP.

| `SESSION_DRIVER` | `database` | مخزن الجلسات لتسجيل الدخول عبر الويب |
| `SITEMAP_SCHEDULE` | `0 * * * *` | تعبير cron لإعادة توليد خريطة الموقع |

| `HONEYPOT_ENABLED` / `HONEYPOT_SECONDS` | `true` / `1` | الحماية من الرسائل المزعجة في التسجيل ونسيان كلمة المرور |

### تسجيل دخول المدير

يسجّل الطاقم (المديرون وكتّاب الأسئلة والمراجعون) الدخول عبر بوابة الواجهة الخلفية على `/admin/login`، ويسجّل اللاعبون عبر `/login` في الواجهة العامة. ترفض كل بوابة نوع الحساب الآخر. سجّل الدخول على `/admin/login` بحساب المدير المزروع:

| الحقل | القيمة الافتراضية |
| --- | --- |
| البريد الإلكتروني | `admin@fakkroun.test` |
| كلمة المرور | `password` |

يُنشأ المدير بواسطة `database/seeders/AdminUserSeeder.php`، ويُزرع دائماً، بما في ذلك عند تشغيل `php artisan db:seed --class=MinimalDatabaseSeeder` و`ConfigDatabaseSeeder`. لتجاوز القيم الافتراضية قبل الزرع، اضبطها في `.env`:

```dotenv
ADMIN_NAME="Admin User"
ADMIN_EMAIL=admin@fakkroun.test
ADMIN_PASSWORD=change-me-now
```

> **غيّر كلمة مرور المدير قبل النشر.** `password` قيمة افتراضية معروفة. إعادة تشغيل الزارع تحدّث كلمة مرور المدير الحالية إلى قيمة `ADMIN_PASSWORD` الحالية، لذا يمكنك أيضاً تعيين كلمة جديدة بـ`php artisan db:seed --class=AdminUserSeeder`.

### حسابات أخرى يزرعها الزارع

يُنشئ `php artisan db:seed` أيضاً الحسابات التجريبية التالية (لا ينشئها الزارعون الأدنى):

| الدور | البريد الإلكتروني | كلمة المرور | ملاحظات |
| ---- | ---------------- | ---------- | ------- |
| مستخدم | `test@example.com` | `password` | مستخدم قياسي موثّق |
| معلن | `ads@carthage-books.test`، `communication@univ-sousse.test`، `contact@ecole-ibnkhaldoun.test`، `hello@green-tunisia.test`، `club@jeunes-savants.test` | `password` | معلنون تجريبيون (واحد لكل نوع)، من `AdvertiserDemoSeeder`؛ يظهرون تحت الإدارة ← الإعلانات ← المعلنون |

يُنشأ عشرة مستخدمين عشوائيين إضافيين بالكلمة نفسها `password`، وتأتي بياناتهم من `UserFactory`.

يُنشئ `OwnerUserSeeder` حساب لاعب موثّقاً للعنوان `mohammad.trabelsi@gmail.com`. وهو ليس ضمن أي مستوى من مستويات الزارع؛ شغّله وحده. اضبط `OWNER_PASSWORD` لاختيار كلمة المرور، أو اتركه غير مضبوط لتُولَّد كلمة مرور عشوائية وتُطبع مرة واحدة. إعادة التشغيل تُبقي كلمة المرور الحالية ما لم يُضبط `OWNER_PASSWORD`.

```bash
OWNER_PASSWORD='choose-a-strong-password' php artisan db:seed --class=OwnerUserSeeder --force
```

## طبقة الخدمات

يُقرأ كل نموذج ويُكتب **فقط عبر خدمته الخاصة**. لا يستدعي أي مكوّن أو متحكم أو أمر أو مهمة أو زارع أو خدمة أخرى النموذج بشكل ثابت (`Post::query()` و`Post::create()` و`Post::find()` ...)، بل يطلب خدمة النموذج.

- كل خدمة تعلن النموذج الذي تملكه وتستخدم السمة `App\Services\Concerns\ManagesModel`، التي توفّر `query()` و`find()` و`findOrFail()` و`findBy()` و`all()` و`count()` و`create()` و`firstOrCreate()` و`updateOrCreate()` و`update()` و`save()` و`delete()` و`withTrashed()` و`onlyTrashed()`. ويمكن للخدمة أن تستبدل أيّاً منها بنسخة خاصة بالمجال (مثلاً `PostService::create()` يزامن الوسوم أيضاً).
- نماذج التطبيق العامة تعيش في `app/Services` (`PostService` و`UserService` ...)؛ ونماذج المجال تكون خدمتها بجانبها، مثلاً `App\Domain\Gameplay\GameService` لنموذج `Game`، أو `QuestionService` لنموذج `Question`.
- تتلقى كلاسات المجال الخدمات التي تحتاجها عبر المُنشئ (constructor)؛ وتحقنها مكوّنات Livewire في الإجراءات أو تحلّها عبر `app()`.
- يفشل `tests/Feature/Architecture/ServiceLayerTest.php` عندما لا يكون للنموذج خدمة، أو عندما يستعلم كود خارج تلك الخدمة عن النموذج مباشرة.

## ملاحظات الميزات

هذه الميزات تعمل مباشرة، لكنها سهلة الإغفال في الكود.

- **إحصاءات الزيارات.** يسجّل `TrackVisit` طلبات `GET` الناجحة للصفحات بعد إرسال الاستجابة، فلا يُبطئ التتبع أي صفحة. يتجاوز منطقة الإدارة و`/api` وطلبات Livewire وتبديل اللغة وتسجيل الخروج و`/up` والروبوتات الشائعة. تظهر الإجماليات في لوحتي الإدارة والمستخدم.
- **إشعارات CRUD.** يراقب `CrudNotificationObserver` النماذج المدرجة في `config/crud_notifications.php` (المقالات والفئات والمستخدمون والإعدادات افتراضياً). عند الإنشاء أو التعديل أو الحذف أو الاستعادة، يخزّن `CrudActionNotification` في جدول `notifications` لكل مستخدم بدور `admin`، باستثناء الشخص الذي أجرى التغيير. تُتجاهل التحديثات التي تمسّ فقط `updated_at` أو `updated_by` أو `remember_token` أو `deleted_at`، فلا يُشعَر أحد بتسجيل دخول «تذكّرني». يرى المديرون عدد الإشعارات غير المقروءة في جرس الشريط العلوي، ويديرون القائمة على `/admin/notifications` (تصفية، وتعليم واحد أو الكل كمقروء). لمراقبة نموذج آخر، أضفه إلى ملف الإعدادات هذا.
- **صحة النظام.** ينفّذ `SystemHealthService` فحوصات مستقلة لقاعدة البيانات والذاكرة المؤقتة والطابور، ويعرضها في بطاقة صحة النظام في لوحة الإدارة. لا يؤدي فشل فحص واحد إلى تعطيل الصفحة.
- **وضع الصيانة.** يُفعَّل من **الإدارة ← الإعدادات**. يعرض `EnforceMaintenanceMode` صفحة 503 للزوار وJSON على `/api`. يبقى المديرون وصفحتا تسجيل الدخول والتحقق الثنائي وتبديل اللغة و`/up` متاحة.
- **تنسيق التاريخ.** تختار إعدادات الإدارة تنسيقاً واحداً للتواريخ المعروضة في سجل النشاط وقائمة المستخدمين. الخيارات معرّفة في `Setting::DATE_FORMATS`.
- **صور الغلاف.** يمكن أن تملك المقالات صورة غلاف، تُرفع في نموذج المقال وتُخزَّن على القرص `public`، وتظهر في `/blog` وفي صفحة المقال. شغّل `php artisan storage:link` أولاً.
- **خريطة الموقع (XML).** يسرد `php artisan sitemap:generate` (`SitemapService`) المسارات المسماة في `config/sitemap.php` (`home` و`about` و`docs` و`blog`) وكل مقال يقدّمه `/blog/{slug}` فعلاً (منشور وغير محذوف). تُبنى العناوين من `APP_URL`، ولا تحتوي على معلمات استعلام، وتُزال منها التكرارات. تكون `<lastmod>` هي `updated_at` للمقال (وأحدث قيمة لـ`/blog`)؛ ولا تحصل الصفحات الثابتة عليها، وتُحذف `changefreq` و`priority`. تُولَّد الملفات وتُتحقق ثم تُكتب في ملف مؤقت وتُعاد تسميتها، فإذا فشل التشغيل يبقى ملف الخريطة السابق سليماً وتخرج الأمر برمز خطأ. وفوق 50,000 عنوان يكتب `sitemap-1.xml` و`sitemap-2.xml` ... خلف فهرس خرائط. يُعاد توليدها كل ساعة (`SITEMAP_SCHEDULE`، مع `withoutOverlapping`)، ويضع `PostSitemapObserver` في الطابور `GenerateSitemapJob` بلا تكرار كلما تغيّر مقال منشور. لا تُدرج أبداً مسارات المصادقة والحساب والإدارة وواجهة API واللغة؛ والفئات لا صفحة عامة لها فلا تُدرج كذلك. يُخدَم `/robots.txt` بدالة مسار في `routes/web.php`، ويضيف سطر `Sitemap:` بعد وجود الملف.
- **بريد الدعم.** يُضبط في إعدادات الإدارة ويُخزَّن مع إعدادات الموقع.
- **اللاعبون الضيوف.** اللعب لا يحتاج إلى حساب؛ أما إنشاء غرفة فيحتاجه. في `/play/join` (وروابط الدعوة `/join/{code}`)، يدخل الزوار بلا جلسة اسماً مستعاراً ورمز الغرفة. ينشئ `GuestPlayers` بعد ذلك مستخدماً مؤقتاً مسجّل الدخول، معلَّماً بـ`is_guest` وبدور `player`، حتى يواصل محرك اللعب العمل بمعرّفات المستخدمين. يُخرج الوسيط `registered` (`EnsureUserIsRegistered`) الضيوف من الجلسة ويرسلهم إلى `/login` من كل صفحة حساب، بما في ذلك `/play` (إنشاء غرفة). ويرفضهم `RoomService::create` أيضاً. يُستبعد الضيوف من لوحة المتصدرين، ولا يحصلون على إنجازات، وليس لهم صفحة ملف شخصي. يحذفهم `model:prune` بعد أسبوع من انضمامهم (مجدول يومياً).

## التعريب

تُضبط اللغات المتاحة في `config/app.php` ضمن `available_locales`:

```php
'available_locales' => [
    'en' => ['label' => 'English', 'dir' => 'ltr'],
    'ar' => ['label' => 'العربية', 'dir' => 'rtl'],
    'fr' => ['label' => 'Français', 'dir' => 'ltr'],
],
```

يطبّق الوسيط `SetLocale` اللغة التي اختارها المستخدم للجلسة في كل طلب، وتتولى صفحة Livewire `pages::locale` (`/language/{locale}`) التبديل، ويُستنتج اتجاه النص (`ltr`/`rtl`) تلقائياً لعرض RTL صحيح. لإضافة لغة، أضف مدخلاً هنا ومجلد `lang/{locale}` مطابقاً يحوي الملفات نفسها الموجودة في `lang/en`.

يفحص `php artisan translations:sync` (`app/Console/Commands/SyncTranslationKeys.php`) مجلد `resources/` بحثاً عن مفاتيح الترجمة، وينشئ ملفات اللغة الناقصة، ويكمل المفاتيح الغائبة في اللغات الأخرى. الخيارات:

- `--locales=en,fr,ar`: اللغات المراد مزامنتها (الافتراضي: الكل)
- `--base=en`: اللغة المرجعية
- `--dry-run`: يعرض التغييرات دون كتابتها
- `--clean`: يحذف أيضاً المفاتيح التي لا تستخدمها أي واجهة

تُخزَّن الحزم كمصفوفات متداخلة، فيُقرأ `home.hero.title` ويُكتب كـ`['hero']['title']` في `lang/{locale}/home.php`. تُتجاهل المفاتيح المبنية وقت التشغيل (`__('about.stat_'.$key)`) لأنها ليست مفاتيح حقيقية؛ ويحتفظ `--clean` بالمفاتيح تحت مثل هذه البادئة. تُسبق القيم غير المترجمة بـ`[TODO]` لتسهل مراجعتها وإكمالها.

## الأدوار والصلاحيات

تُزرع الأدوار والصلاحيات بواسطة `RolesAndPermissionsSeeder`. يُمنح دور `admin` الصلاحيات التالية:

- `view admin dashboard`
- `manage users`
- `manage posts`
- `manage categories`
- `view activity log`
- `manage settings`
- `manage tags`
- `view system health`
- `manage backups`

تحقّق من صلاحية المدير في الكود عبر `$user->isAdmin()` أو عبر اسم الوسيط `admin` للمسار.

تمر إجراءات المقالات والفئات بالإضافة إلى ذلك عبر `App\Policies\PostPolicy` و`App\Policies\CategoryPolicy`. عرض المقالات وإنشاؤها يتطلبان `manage posts`. أما تعديل المقال أو نقله إلى سلة المحذوفات أو استعادته أو حذفه نهائياً فيتطلب أيضاً أن يكون المستخدم كاتب المقال، إلا إذا كان مديراً. الفئات مشتركة، لذلك تتطلب كل إجراءات الفئات `manage categories` فقط.

## توليد مورد جديد

```bash
php artisan starter:make-crud Article
```

ينشئ هذا الأمر نموذج `Article` والترحيل والمصنع و`ArticleService` و`ArticlePolicy` و`ArticleModuleTest`، باستخدام الحذف الناعم وتسجيل النشاط. ولا يستبدل أي ملف موجود أبداً. بعد ذلك، أضف الصلاحية `manage articles` إلى `RolesAndPermissionsSeeder`، ثم أضف المسارات ومتحكم API والشاشات التي تحتاجها.
